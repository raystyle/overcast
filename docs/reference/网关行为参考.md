# 网关行为参考

> 类型: reference
> 事实源: deploy/config.example.yaml、REQ-001 实测证据、design-001 第 1.1 节机制源头

## 状态码与换 key

同一次请求内,conductor 换 key 循环的行为:

| 上游状态 | 同一次请求 | 冷却 |
| --- | --- | --- |
| 400、409、413、422 及 body 判为请求错误 | 不换 key,原样返回 | 不惩罚 |
| 401 | 换下一把 | 30 分钟 |
| 402、403 | 换下一把 | 30 分钟 |
| 429 | 换下一把 | 配额退避,尊重 Retry-After,有下限 |
| 408、500、502、503、504、520 至 526 | 换下一把 | 瞬时冷却(配置 0 沿用 60 秒) |
| 拨号、TLS、连接重置 | 换下一把 | 另标传输错误,不按请求错误停转 |

实测佐证:401 换 key(trace `[98c55a49]`)、400 不轮转(`[4feb9f1d]`)、429 额度尽同请求换 key(`[216049cb]`),证据在 REQ-001 判据条。

## 流式语义

首包之前失败,模型池与下一把 key 都能接;首包已转给客户端后,不换 key 不重放,错误转发客户端,断流由 agent 重开一轮(中途接半段 SSE 上下文对不齐且双计费,不做)。

## 供应池

同别名多上游条目即 failover 池,round-robin 在未冷却条目间轮转。现行:两把智谱 key(5 小时窗限,code 1308 形态 429)+ zyuncs 备供应商(`llm.api.zyuncs.com`,模型名 `z-ai/glm-5.3` 形)。双智谱同窗尽时 zyuncs 接力,2026-10-12 实测四笔全 200(REQ-001 演进)。

## key 形制

- openai-compatibility 组:多 key 用 `api-key-entries` 列表
- claude-api-key 组:必须拆条目、每条一个 `api-key`(该组不认 `api-key-entries`,载入空 key 上游 401「Header中未收到Authorization参数」)
- xai-api-key 组:legacy 形每条目一把 key,无 name 与 keys 字段
- 两把 key 必须同种产品(通用 key 与编码套餐 key 的 base 不同,不混填);不要把多把 key 配成多个模型别名,别名池是换上游,不是换账户

## 已知边界

| 边界 | 行为 |
| --- | --- |
| port 必写 | config 缺根级 `port: 8317` 时上游监听随机端口,外部一律连不上 |
| responses 面走 xai 组 | 智谱 `/api/v1` 是 Responses-only 面,openai-compatibility 执行器 chat 翻译在该 base 必 403 |
| 裸名 glm-5.3 | 经 /v1/messages 路由 200,anthropic 原生 id 形,落 claude 执行器 |
| `[1m]` 后缀 | 纯客户端参数,网关别名不带;带后缀直打网关 400 unknown provider |
| anthropic 面无前缀缓存 | 同 key 同 1923-token 前缀两发 cache_read 均 0;session-affinity 无缓存收益,保持 false |
| 冷却态不落盘 | `save-cooldown-status` 默认 false,容器重启冷却清零,双 key 场景可接受 |
| 智谱额度尽形态 | 标准 429 + rate_limit_error + code 1308 + 重置时间与 rate-limit headers,内建规则即接,无需 request-scoped-errors |
| 外部无 key 探测 | `GET /v1/models` 得 401 属预期(鉴权墙在) |
| 怪 body 形态升级阶梯 | 智谱若把失败放 HTTP 200 body 或 400 文案,先配 `request-scoped-errors`,再走二开条件句(见 ADR-0001 与 explanation 上游选型) |
