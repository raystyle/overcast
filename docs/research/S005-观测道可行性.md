## 背景

REQ-002 要全量对话可回溯。范围是网关代理的请求与响应,含流式增量。采集器指定 vector,库指定 ClickHouse。

现网形态来自仓内 compose。镜像 `eceasy/cli-proxy-api:v8.0.23`,容器名 `overcast`,端口 `8317`。卷只有 `config.yaml` 与 `auths`。compose 未写 logging 驱动,也未写 vector。

stdout 上的 `gin` 行有请求 id、状态、耗时。换 key 与冷却的 warn 在 conductor 源文件对应的日志行里。这两类行都不含请求体或响应体。

## 结论与推荐路线

一条主线。现 tag 的配置键拿不到「全量正文」和「热路径零磁盘」同时成立。

主线:CPA 进程内增加一条异步 JSONL 卷。有界队列,队列满或写盘失败只丢观测事件,不改变转发与换 key。文件形态学 Suricata:同一时刻一个活跃文件,按时间改名切开,旧文件只追加不改写。vector 用 `file` source 尾随。ClickHouse 用头表加块表。补丁以小提交给上游,不留分叉。这与 ADR-0001 Consequences 里「CH 若需代码,优先侧车或上游小补丁」一致。

补丁进入官方镜像之前,生产配置保持 `request-log: false`。REQ-002 继续 draft。

备选一:拒绝补丁时,才考虑同 compose 的入口反代做非阻塞 tee。客户端改走反代。反代写盘失败必须继续转发。这一跳本身是新的入口故障面,与「观测不得成为新故障面」冲突更大,所以不作为主线。

备选二:短时排障可打开 `request-log: true`。日志目录用独立卷,并设置 `logs-max-total-size-mb`。这不作为验收路径。

docker stdout 与 json-file 轮换留作状态行采集。它们没有 body,不能当对话源。

## 上游能力盘点

配置有两套拼写,加载时互相展开。源码 `internal/config/config_v8.go` 把旧键映到 v8 路径。`request-log` 对应 `observability.logs.request-log`。`logging-to-file`、`debug`、`logs-max-total-size-mb`、`error-logs-max-files`、`commercial-mode` 同样有旧键。`Config.UnmarshalYAML` 写明两种布局都接受。现网若仍是旧版扁平键,写 `request-log` 即可,不必先改成 v8 嵌套。

### 键与默认

| 键 | v8 路径 | 零值或示例 | 作用 |
| --- | --- | --- | --- |
| `debug` | `observability.logs.debug` | 示例 false | 调试行。含 `Use API key` 与掩码。不含 body |
| `logging-to-file` | `observability.logs.logging-to-file` | 示例 false | true 时应用日志进 `main.log`。false 时走 stdout |
| `logs-max-total-size-mb` | 同组 | 示例 0 | 大于 0 时每分钟删最旧 `*.log`,保住 `main.log` |
| `error-logs-max-files` | 同组 | 示例 10 | 只限制 `error-*.log` 的个数 |
| `request-log` | `observability.logs.request-log` | 示例 false | 记录代理请求与响应。管理路径排除 |
| `commercial-mode` | `server.commercial-mode` | 示例 false | true 时不挂请求日志中间件,并强制 `RequestLog` 为 false |

字段定义:`internal/config/sdk_config.go` 的 `RequestLog`,`internal/config/config.go` 的 `Debug`、`LoggingToFile`、`CommercialMode`。示例在 tag 的 `config.example.yaml` 第 1087 到 1105 行,以及 `server.commercial-mode`。

帮助页仍把 `request-log` 写成隐藏项,并警告单条日志可能到 10MB 以上。该句是 2026-10-12 检索摘录。tag 源码的写入函数没有 10MB 截断。

管理 API 有 `GET` 与 `PUT` `/v0/management/request-log`。配置热加载会调用 `SetEnabled`。见 `internal/api/handlers/management/config_basic.go` 与 `internal/api/server_reload.go`。

仓内 `deploy/config.example.yaml` 与 `deploy/docker-compose.yml` 都没有这些观测键。本轮未读现网渲染文件。

### debug 与 gin 行

`debug: true` 才打印选 key。`sdk/cliproxy/auth/conductor_execution.go` 的 `debugLogAuthSelection` 在 Debug 级别输出 `Use API key` 加 `HideAPIKey`。默认 info 级别没有这行。

stdout 格式在 `internal/logging/global_logger.go` 的 `Format`。行内请求 id 只用 UUIDv7 的末 8 个字符。`gin` 消息是状态、耗时、客户端 IP、方法与路径。见 `internal/logging/gin_logger.go`。没有 body。

失败 warn 在 `conductor_execution.go` 约第 1978 行。文本含 provider、model、auth 与错误。这是失败记录,不是每次轮换都有的一行。冷却汇总 warn 在 `conductor_selection.go`。

### request-log 的粒度与格式

打开后,一次请求一个文本文件,不是单文件 JSONL。文件名形如 `v1-messages-2025-12-23T195811-` 加请求 id 末 8 位,再加 `.log`。见 `generateFilename`。文件正文有 `REQUEST INFO`、`HEADERS`、`REQUEST BODY`,以及按尝试编号的 `API REQUEST N` 与 `API RESPONSE N`。正文没有单独的完整请求 id 字段。模型在 JSON body 里。身份在 `Auth:` 行:provider、auth_id、label,api_key 经 `HideAPIKey` 只留首尾。见 `formatAuthInfo` 与 `internal/util/provider.go`。

同一次请求里的换 key 会变成多个 `API REQUEST N`。每个尝试各有 Auth 行。这是现成的轮换分段,条件是 `request-log` 为 true。

流式有两条捕获,行为不同。

上游侧:`AppendAPIResponseChunk` 在 `request-log` 为 true 时,把每行 SSE 追加进临时文件。`FileBodySource.AppendBytes` 每次打开、写入、关闭。Claude 流在 `claude_executor_stream.go` 里先调用这个函数,再把事件交给下游。写盘延迟会加在转发给客户端之前。写失败只打 warn,并退回内存,不把请求标成失败。

下游侧:响应包装器先写客户端,再把副本送进容量 100 的通道。通道满则丢掉该块。见 `response_writer.go` 的 `Write`。另一层 `FileStreamingLogWriter` 也是容量 100,满则丢。见 `WriteChunkAsync`。因此下游副本会丢增量。上游 `API RESPONSE` 段才是较全的流式文本,代价是同步磁盘。

请求结束时 `Finalize` 组装最终文件。`request_logging.go` 在 `c.Next()` 之后调用它,错误不回写给客户端。流式的 `Close` 会等后台刷盘结束,占用该请求的 goroutine,但此时字节多半已经发给客户端。

非流式在请求开始时 `io.ReadAll` 整个 body,再交给处理器。大提示词会先占内存,再进入上游。

`commercial-mode: false` 时,即使 `request-log: false`,中间件仍然挂着,用于错误文件。已知长度且不超过 1 MiB 的 body 会预先读入内存。更大的 body 在读取时同步抄到临时文件,上限 32 MiB。见 `shouldCaptureRequestBody` 与 `attachDeferredRequestBodyCapture`。GET 除 `/v1/responses` 的 websocket 升级外跳过。管理路径不记。`commercial-mode: true` 时这层中间件不安装。本 tag 里该开关只碰到请求日志,没有第二处中间件被关掉。

日志目录:`ResolveLogDirectory`。环境变量 `WRITABLE_PATH` 优先,否则 `logs`,不可写再落到 `auth-dir/logs`。镜像 `WORKDIR` 是 `/CLIProxyAPI`。compose 没有日志卷,也没有该环境变量。未设置时,文件在容器可写层,重建容器即丢失。`auths` 卷只有回退路径才会被写入。

### 性能代价

`request-log: false` 且 `commercial-mode: false` 时,流式上游路径在函数入口返回,不写盘。请求体仍可能为了错误日志被读一遍或抄一遍。

`request-log: true` 时,每条上游 SSE 行一次同步 open 与 append。首个响应头之前,`LogStreamingRequest` 还要创建临时文件,发生在向客户端 `WriteHeader` 之前。磁盘变慢会拉长首字节与每个增量。磁盘满时上游捕获失败被吞掉,转发继续。这仍把磁盘延迟留在热路径上。

本轮没有在现网打开该键,也没有压测毫秒数。上面是源码路径,不是实测时延。

## Suricata 可搬与不可搬

Suricata 8.0.7 文档同日打开。EVE 默认把多类事件写入一个 `eve.json`。一行一个 JSON 对象。第三方按文件尾随。

内建轮换:文件名可带 `strftime`,`rotate-interval` 支持 minute、hour、day,以及 `30s` 这类相对值。到点写新文件。旧文件不再被该输出写入。删旧文件仍归外部工具。

外置轮换:官方 logrotate 示例使用 `create`、`nocompress`、`rotate 3`。`postrotate` 向 pid 发 `SIGHUP`。Suricata 收到后关闭并重新以追加方式打开。文件已被改名时,会新建空文件。示例不是 `copytruncate`。

缓冲:默认 `buffer-size` 为 0,写出接近同步。非零缓冲才可能在崩溃时丢掉尚未刷盘的尾部。`heartbeat.output-flush-interval` 用来限制缓冲停留时间。

HTTP body 不是默认全量。payload 与 http-body 是单独开关,并有 `payload-buffer-size` 这类上限。MQTT 另有 `string-log-limit`。EVE 的常态是小事件,不是整段对话。

### 可搬

- 单活跃文件,只追加,一行一个事件。尾随者用偏移即可,不必解析一请求一文件。
- 轮换用改名或新文件名。写者放开旧文件。采集者把旧文件读到 EOF。
- 盘容靠删已完成的旧文件。不靠截断写者仍持有的那个 inode。
- 压缩放在采集者读完之后。官方示例 `nocompress`。
- 观测缓冲与转发分开。缓冲丢失只影响观测。

### 不可搬

- Suricata 的 `SIGHUP` 重开。CPA 的 request-log 没有这个信号,它本来就是一请求一文件。
- `copytruncate`。它不是 Suricata 官方示例。Vector 文档写明默认 logrotate 的改名无需特殊配置。`copytruncate` 需要 `delaycompress`,并把第一个已轮换文件放进 `include`。文档把漏读窗口写成很小,本轮没有复现该窗口。
- 把整段提示词或整段 SSE 合成一行却不设上限。Vector `file` 的 `max_line_bytes` 默认 102400。超限行被丢弃。
- EVE 默认不存全量 HTTP body。对话回溯不能照抄「只存元数据」的默认。

### Vector 尾随行为

文档同日打开,组件状态 stable。

- `include` 支持 glob。发现间隔默认 `glob_minimum_cooldown_ms` 1000。短生命文件有漏发现窗口。
- 检查点在每次成功读取之后写入 `data_dir`。重启从偏移继续。
- 指纹默认 `checksum`,对文件开头 N 行做 CRC,默认 1 行。行数不足 N 的文件先不读。`device_and_inode` 可选。文档推荐 checksum,因为 inode 会复用。
- 改名轮换:保持旧句柄直到读完,并发现新文件。无需额外配置。
- 时间切分的单逻辑流建议 `oldest_first: true`,避免忙时先读新文件、打乱顺序。
- gzip:能读,但不能对已有检查点的压缩文件继续 seek。进程退出前应读完,或不要压缩尚未读完的文件。
- `remove_after_secs` 在 EOF 之后等待再删。文档没有写明必须等 ClickHouse 确认。本轮未验证删除与投递的先后。验证动作:投递失败时确认文件仍在。
- 输出是每行一个事件,字段有 `file`、`message`、`timestamp`。多行文本要另配 `multiline`。CPA 的 `.log` 是多段文本,直接当行读会被拆开。

## 取流方案对照

| 方案 | 流式增量 | 热路径 | 盘容 | 复杂度 | 观测故障时请求 |
| --- | --- | --- | --- | --- | --- |
| A. 打开 `request-log`,vector 读 `*.log` | 上游段按行同步落盘,较全。下游通道满则丢块 | 每行 SSE 同步 open 与写。首包前创建临时文件。大 body 先读入内存 | 一请求一文件。`logs-max-total-size-mb` 大于 0 才删旧文件。默认 0 不删。无独立卷则写在容器层 | 只改配置。vector 还要拼多行文本。文件名只有 8 位 id | 写失败不改状态码。磁盘变慢会拉长增量与首字节 |
| B. 入口反代非阻塞 tee,JSONL,vector `file` | 反代必须逐块转发并复制。复制队列满则丢观测 | CPA 本身不加磁盘。客户端多一跳本地转发 | 单文件按小时切开,删旧文件即有界 | 新进程、新入口、客户端改地址。要证明写盘失败仍转发 | 反代崩溃或配错会中断全部请求。写盘失败若实现为丢事件,则只丢观测 |
| C. docker json-file 轮换,vector 读容器日志 | 没有 body,也没有逐块 SSE | 维持现状。应用日志在 stdout | compose 未设 `max-size`。本轮未读宿主机 daemon 配置 | 低。接上也不含对话 | 日志驱动故障通常不改变响应。对话数据仍然没有 |
| 主线补丁。进程内异步 JSONL | 一块一行。队列满记丢弃计数 | 热路径只做非阻塞入队。写盘在别的 goroutine | 小时文件加外部删除。卷容量按采集中断窗口估算 | 上游小补丁,不留分叉。镜像 tag 要等含补丁的版本 | 队列满或磁盘满只丢事件。转发与换 key 保持现语义 |

A 的 vector 侧还有第二个问题。`file` source 按行切。CPA 日志是多行栏目。不经重组就不能按请求 id 查询。一请求一文件在高并发下还会提高打开文件数。`glob_minimum_cooldown_ms` 默认 1 秒,很短的文件可能在被看见前已被清理器删除。

C 不能补上 body。`logging-to-file: false` 时 gin 与 conductor 行在 stdout。docker 默认 json-file 只是这些行的外包装。

## schema 与留存

下列库表是草案,本轮没有连接 ClickHouse,也没有执行。

两表,不用单表宽行。宽行要把整段流式响应塞进一格。单行容易超过 Vector 的 102400 字节丢弃线,也难以按增量序号回放。头表负责按时间、模型、身份筛选。块表负责按请求 id 按序号回放。

身份用 `auth_id`,外加 `HideAPIKey` 那种首尾提示。不存上游 token 原文,不存网关访问 key 原文。8 位短 id 只作对照旧日志的列。新事件写入完整 UUIDv7。现 stdout 不打印完整 id,补丁需要把完整 id 写入 JSONL。

```sql
CREATE TABLE overcast.dialog_request
(
    started_at DateTime64(3, 'Asia/Shanghai'),
    request_id UUID,
    short_id FixedString(8),
    model LowCardinality(String),
    client_alias LowCardinality(String),
    path LowCardinality(String),
    status UInt16,
    latency_ms UInt32,
    attempt_count UInt8,
    auth_ids Array(String)
)
ENGINE = MergeTree
PARTITION BY toYYYYMMDD(started_at)
ORDER BY (started_at, model, request_id)
TTL started_at + INTERVAL 90 DAY;

CREATE TABLE overcast.dialog_event
(
    event_time DateTime64(3, 'Asia/Shanghai'),
    request_id UUID,
    seq UInt32,
    kind LowCardinality(String),
    auth_id String,
    auth_hint String,
    status UInt16,
    payload String
)
ENGINE = MergeTree
PARTITION BY toYYYYMMDD(event_time)
ORDER BY (request_id, seq)
TTL event_time + INTERVAL 14 DAY;
```

`kind` 取值固定为:`client_request`、`upstream_attempt`、`sse`、`rotation`。`rotation` 一行对应一次换 key,字段用 `auth_id`,不靠掩码是否碰巧唯一。`payload` 用 String,里面是该块的 JSON 文本。单行在写入前切到不超过 64 KiB。Vector 的 `max_line_bytes` 设为 131072,高于该上限。

查询:

- 按请求回放:`dialog_event` 上 `request_id` 且 `ORDER BY seq`。
- 按时间与模型:`dialog_request` 的排序键前两列。
- 按 key 看轮换:`kind = 'rotation'` 或 `upstream_attempt`,过滤 `auth_id`。

留存提案,数字待裁:块与正文 14 天。请求头 90 天。采样先不做。按请求 id 回溯时,被抽掉的请求无法复原。超载时丢新事件并计数,优于随机抽样。

卷上的 JSONL 只是 vector 的缓冲,不是库。建议按小时切文件,保留 48 小时,供采集中断时补读。48 小时是提案,要按峰值 body 大小再算卷容量。ClickHouse 的 TTL 才是查询留存。

### Vector 到 ClickHouse

sink 文档同日打开。状态 stable,交付 at-least-once。默认 `format: json_each_row`,一行一个 JSON 对象。默认 `compression: gzip`,另有 `zstd`、`snappy`、`zlib`、`none`。

批写默认:`batch.max_bytes` 为 10000000,指压缩前字节。`batch.timeout_secs` 为 1。未写 `batch.max_events` 的默认个数。满足大小或年龄之一即刷。

建议起步参数,尚未压测:

- `compression: zstd`。正文大,zstd 在文档的枚举里。
- `batch.max_bytes: 10000000`,`batch.timeout_secs: 1`。先用默认。
- `skip_unknown_fields: true`。多出来的 vector 字段不让插入失败。
- `date_time_best_effort: true`。时间用 RFC3339 时需要。
- `buffer.type: memory`,`buffer.when_full: drop_newest`。默认是 `block`。`block` 会把反压传到 file source,卷会堆到轮换。观测道选择丢新事件。
- 两个 sink,或一个 remap 后按 `kind` 分到两张表。
- `healthcheck.enabled: true`。库不可达时 vector 启动失败应只影响采集容器。

部署形态:vector 与网关同 compose,sidecar。只读挂载 JSONL 卷,自己的 `data_dir` 用独立小卷保存检查点。不装成宿主机常驻进程,避免与容器生命周期分叉。ClickHouse 不进网关容器。端点、库名、账号留在金库渲染的 vector 配置里,不进仓。

vector 停机或库拒绝写入时,网关仍转发。卷按 48 小时删除,超出的观测丢掉。这是预期丢失,不是请求失败。

## 热路径旁路

| 故障 | 对请求 |
| --- | --- |
| vector 退出 | 主线下无影响。JSONL 继续写,旧文件到期删除 |
| ClickHouse 拒绝或不可达 | `drop_newest` 时丢事件。请求路径无 vector |
| JSONL 卷满 | 补丁必须丢事件并计数。禁止在写盘系统调用里堵住 SSE 循环 |
| 打开现 tag 的 `request-log` | 磁盘变慢会拉长每个上游增量。写失败不改 HTTP 状态 |
| 入口反代崩溃 | 全部请求失败。所以反代不是主线 |
| docker 日志驱动异常 | 不提供 body。对请求通常无影响 |

## 开放问题与判据建议

回填 REQ-002 前需要人裁的事项:

1. 是否接受上游小补丁作为观测主线。ADR 允许侧车或小补丁。本档把小补丁放在主线,因为入口反代会变成必经故障面。
2. ClickHouse 跑在哪台机器。本仓与本轮都没有库的地址。
3. 14 天正文、90 天请求头、卷上 48 小时,这三个数是否接受。
4. 提示词与回答全文入库后的访问范围。本档不设计权限。
5. `auth_id` 在进程重启后是否仍指向同一把上游 key。源码有该字段。稳定性本轮未对现网文件核对。
6. 现网是否已设 `commercial-mode` 或 `WRITABLE_PATH`。本轮未读现网配置。

判据建议,用来替换现稿里尚未可测的三句:

1. 全量事件写入网关进程外的 JSONL 卷。vector 只读该卷。不把 docker stdout 当作 body 来源。
2. 采集队列满或卷不可写时,丢事件并增加计数。同一请求的 HTTP 状态与换 key 行为与采集关闭时一致。验证时拔掉卷或停 vector,短对话仍返回 200。
3. ClickHouse 中,给定完整 `request_id`,块表按 `seq` 返回客户端请求、每次上游尝试、SSE 块与换 key 行。给定时间范围与模型,头表能列出请求。给定 `auth_id`,能列出 `rotation` 或 `upstream_attempt`。表中无上游 token 原文。
4. 块表 TTL 与头表 TTL 使用已裁定的天数。超过 TTL 的正文查不到。未超过的请求仍能按 id 回放。
5. 单行 JSONL 不超过 64 KiB。Vector `max_line_bytes` 高于该值。超长正文拆成多条 `seq`,不依赖默认 102400 的丢弃。

现稿第一句写「容器日志出口」。容器 stdout 没有 body。建议改成 JSONL 卷,避免验收时去接 docker 日志。

## 关键结论

1. tag v8.0.23 有 `request-log`。旧键与 `observability.logs.request-log` 都能载入。默认 false。打开后记录请求头、请求体、每次上游尝试与上游 SSE 行。管理路径排除。[实证] `config_v8.go`,`sdk_config.go`,`config.example.yaml`,`request_logging.go`。
2. `debug` 与 gin stdout 不含 body。stdout 的请求 id 是 UUIDv7 末 8 位。换 key 的明文 warn 是失败与冷却,不是每次轮换一行。[实证] `global_logger.go`,`gin_logger.go`,`conductor_execution.go`,`conductor_selection.go`。
3. `request-log` 的上游 SSE 捕获在转发给客户端之前同步写盘。下游日志通道容量 100,满则丢块。写失败不改变响应。磁盘变慢会进入热路径。本轮无时延实测。[实证] 调用顺序与通道代码。[假设] 时延幅度。验证动作:隔离卷上打开该键,比较首字节与增量间隔,测完即关。
4. 文件是一请求一个多行 `.log`,不是 Suricata 那种单文件 JSONL。Vector `file` 按行读取,默认丢掉长于 102400 字节的行。[实证] `generateFilename` 与 Vector 文档默认值。
5. Suricata 可搬的是只追加、改名轮换、外部删旧、采集者尾随。官方轮换示例是 `create` 加 `SIGHUP`,另有 `rotate-interval` 新文件。`copytruncate` 不是该官方示例。Vector 对改名无需特殊配置,对 `copytruncate` 要求 `delaycompress` 与包含已轮换文件。[实证] 两份 Suricata 页与 Vector File Rotation 节。漏读窗口大小本轮未复现。[假设] 验证动作:若仍评估 `copytruncate`,用空载文件做一次轮换,对账行数。
6. 主线用进程内异步 JSONL 加 vector sidecar 加两表。入口反代与现成 `request-log` 都不是验收路径。[推断] 依据是结论 3、4 与「观测故障不得挡住 failover」。验证动作:补丁评审时用队列满与卷只读两条用例,确认状态码与换 key 不变。
7. schema、TTL 天数、批写用 zstd、`drop_newest` 均为提案。文档证明这些参数存在,不能证明它们在本网关流量下合适。[假设] 验证动作:库就绪后用一天真实流量看卷占用、丢弃计数与按 id 回放。
8. 帮助页「单条 10MB+」与 tag 源码不一致。源码未见该上限。[实证] 检索摘录与 `logRequest`。以 tag 源码为准。

## 对照分流

等价不吸收:docker 日志轮换、gin 行、`debug` 行。它们已经存在,只覆盖状态与失败,不覆盖对话正文。

真新增吸收:单文件 JSONL、按小时改名、vector `file` source、头表加块表、完整请求 id、`auth_id` 轮换行、队列满丢事件。这些现 tag 没有。

留档:`request-log` 的文本文件与错误日志中间件。排障可短时打开。不进入 REQ 验收。`copytruncate` 留档为 Vector 兼容项,不采用。入口反代留到补丁被拒之后再议。
