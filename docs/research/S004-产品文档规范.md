## a. 结论与推荐框架

1. 产品页用 Diátaxis 当罗盘:tutorial 是课,how-to 是已胜任者的操作步骤,reference 是按对象结构排列的事实,explanation 是为什么。罗盘表:动作加学技能归 tutorial,动作加干活归 how-to,认知加干活归 reference,认知加学习归 explanation。[实证] https://diataxis.fr/start-here/ 四类定义与 compass 表,2026-10-12 打开。

2. 目录从已有页里长出来。首批不建立四个空目录。作者先改眼前一页:标类型,把另一种需求的段落挪走或改成链接。[实证] https://diataxis.fr/how-to-use-diataxis/ 写明不要为 tutorials、how-to、reference、explanation 建空结构,结构从改内容里出现。

3. ADR、REQ、研究档案继续按 doc-gov 放在权威层。产品 explanation 用一两句回指 ADR,不改写 Decision。验收勾选只住在 REQ。课题证据只住在研究档。[实证] `doc-gov/SKILL.md` 核心句:需求决策走 ADR/REQ,对外文档面是投影;本仓 `AGENTS.md` 文档框架节与 `docs/adr`、`docs/requirements` 的模板、状态机已经如此。

4. README 只借 standard-readme 的前门习惯:标题与仓库名一致,标题下单独一行说明这是什么,随后是安装与用法的入口,秘密单独成段。不采纳整份规范。[实证] spec.md 自述对象是开源库;必选节含 Contributing 与 License,且 License 必须最后;标题允许在括号里写别名。本仓 `README.md` 标题已是 overcast,全文 34 行。同规范写明短于 100 行的 README 可以不放目录。[推断] 本仓没有贡献流程页,也没有在本轮看到 SPDX 许可证文件,硬套必选节会造出空页。验证动作:批 3 只改 README 的节,不新增 Contributing 或 License,除非届时仓内已有许可证文件。

5. 120 字短描述是该规范对库的要求。本仓前门第一段可以保持一句完整中文,不把 120 字写成门禁。[实证] spec.md 要求 Short Description 短于 120 字符且无标题。[推断] 中文产品句按字符计数容易为门禁改坏句子。验证动作:批 3 评审时只看「标题下第一行能回答这是什么」,不设字符上限,除非另有裁定。

6. 网关类文档的可取形态是三条路径分开:上手、概念、按配置结构排的字段表。Caddy 欢迎页把第一次使用指到 Getting Started,把赶时间指到 quick-starts。Getting Started 自称为 tutorial,有目标清单和前提。quick-starts 写明少解释、先跑起来。Caddyfile 指令页是名称加一句说明的表,语法另节。Getting Started 的对照表写明 JSON 文档自动生成、Caddyfile 文档手写。[实证] 上列四个 Caddy URL,2026-10-12 打开。

7. Traefik 首页先写三种人:初学者、运维、开发者,再写入口、路由、中间件、服务、提供者,链到 reference。同页说明参考节用来查配置项。UDP router 页的配置选项表头是 Field、Description、Default、Required。[实证] https://doc.traefik.io/traefik/ 2026-10-12 打开。字段表头来自同日检索摘录,未整页存档。验证动作:若下一批要照抄表头措辞,先整页打开该 URL 复核。

8. 所打开的 Caddy 欢迎页与 Traefik 首页都没有用 tutorial、how-to、reference、explanation 四个英文名当顶栏。它们按读者要做的事分栏,栏内再分开讲步骤和字段。[实证] 上述两页的链接与标题。全站是否还有别的导航,本轮未爬。[假设] 验证动作:不需要。本推荐不依赖「全站零出现」。

9. 本仓产品面采用同一分工,名称用中文类型标,不把英文四词当成目录名。部署与接入留在 `docs/operations/`,篇首标明 how-to。有一张事实表要独立成页时,再建 `docs/reference/` 下的那一页。有一篇「为什么」要独立成页时,再建 `docs/explanation/` 下的那一页。tutorial 等真有一课再写,首批不出版。[推断] 依据是结论 2 的空目录禁令,加上本仓部署批已是胜任者:手册第 1 到第 4 节已是步骤加验收,符合 how-to,不符合「教一个新手获得技能」的课。验证动作:批 4 之前问部署批是否需要从零课;没有这需求就保持无 tutorial 目录。

10. 文档检查用 lint 守格式与「一处事实一个家」,不从代码生成产品页。[实证] 本仓无网关实现代码;compose 与 `config.example.yaml` 是手写权威。`doc-gov` 的投影句适用于有代码契约可再生成的仓。本仓对外页的权威是模板、REQ、ADR,产品页是它们的短投影。[推断] 生成器没有可投影的代码面。验证动作:批 5 只接入已有禁字检查,不引入文档生成器。

11. 当前要先修的是口径,不是信息架构空缺。文件名和 design-001 的标题仍写三能力。研究索引仍写注入三件与 CH 四件在写。design-001 第 2 节仍按现役注入来写,含旋钮数字与假思考锚。REQ-001 演进节、手册第 8 节、`config.example.yaml` 末行、接入页第 5 节都写注入已剔除。同一直探数字出现在 design-001 第 2.1 节和接入页第 5 节。[实证] 2026-10-12 读到的这些文件。

## d. 职责边界与模板骨架

权威层骨架不改。ADR 保持 Context、Decision、Consequences。REQ 保持 Scenario、Criteria、演进与退役。研究档保持篇首引块、背景、过程、结果、关键结论、参考,对照类加对照分流。[实证] 本仓两份 `0000-template.md` 与 `base-research.md`。

产品页一篇只做一种事。篇首引用块写类型。另一种需求用链接离开本页。

how-to 骨架:

```
# 标题即要完成的事

> 类型: how-to
> 读者: 部署者
> 事实源: deploy/config.example.yaml

## 目标
## 前提
## 步骤
## 验完
## 停手
## 另读
```

步骤里不解释选型,不贴完整判据清单。验完是一条可复制的命令或一个可观察结果。停手写明工位只读、部署批才执行,与本仓边界一致。

reference 骨架:

```
# 标题即被描述的对象

> 类型: reference
> 事实源: deploy/config.example.yaml

## 事实表
## 不在本页
```

事实表的列:名字、值或行为、权威位置。不写「建议你这样排障」。对象结构跟着配置走:路由、三组 key、访问 key、管理面。

explanation 骨架:

```
# 标题即一个为什么

> 类型: explanation
> 裁定: ADR-0001

## 问题
## 裁定一句
## 候选
## 权威
```

候选表可以保留 design-001 第 0 节已有的五行。权威节只放 ADR 与 REQ 的编号,不粘贴 Decision 全文。

tutorial 骨架,有课再启用:

```
# 标题即这一课

> 类型: tutorial

## 学完能做
## 前提
## 课
## 本课不讲
```

课的每步都能做完并看到结果。为什么与字段表放在链接后面。本仓首批没有这篇的读者,见 a 节第 9 条。

前门骨架,只用于根 README:

```
# overcast

一行说明:lan-mac 上的双 token 网关,外加一条留位的观测道。

## 快览
## 下一步
## 秘密
## 边界
```

下一步用链接指向部署手册、接入页、两份 REQ。不在前门重复判据进度以外的细节;进度若写,只写「见 REQ-001」,避免与索引各写一套数字。[推断] 验证动作:批 3 后「7 判据已测 6」只出现在 REQ-001 与需求索引。

退役声明骨架,用于已剔除能力,全文宜短:

```
# 标题写明已剔除

裁定日期、替代编号、证据所在的演进节或 git 提交。
```
