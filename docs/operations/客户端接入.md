# 客户端接入(operations 面)

- 网关:lan-mac 部署位,base-url `http://192.168.88.10:8317`(下称 base-url)
- 鉴权:一律带网关 access key(`access.api-keys` 所发),不是智谱 key;key 值见密码管理器,不进任何入库文件
- 三面端点:Claude Code 走 `/v1/messages`;codex 走 `/v1/responses`;chat 客户端走 `/v1/chat/completions`
- 可用模型名(2026-10-11 经网关 `/v1/models` 与三面实测):`glm-5.3`、`glm-5.3-flash`(messages 面)、`glm-5-turbo`(responses 面)、别名 `zp-glm53-claude` 与 `zp-glm53-codex`

## 1. Claude Code(settings env 形)

`~/.claude/settings.json` 的 env 段,接入相关键:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.88.10:8317",
    "ANTHROPIC_AUTH_TOKEN": "<网关 access key,见密码管理器>",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.3[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.3[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": 1,
    "API_TIMEOUT_MS": "3000000"
  }
}
```

- DEFAULT 三件套(HAIKU/SONNET/OPUS)是接入关键:CC 内部按档位选模型,三档全指网关模型,旧 ANTHROPIC_MODEL/SMALL_FAST_MODEL 两键形会漏档位
- `[1m]` 后缀是 CC 客户端侧 1M 上下文参数,settings 里写带后缀的名,CC 发请求前自己剥掉,网关与上游收到的都是原始名(glm-5.3 / glm-5.3-flash);网关**不配** [1m] 别名(实测对照:别名撤除后裸 claude 照样 200;而带 [1m] 的裸 curl 直打网关 400 unknown provider,证明剥后缀发生在 CC 客户端,不在网关)
- `CLAUDE_CODE_SUBAGENT_MODEL` 同步指 `glm-5.3-flash[1m]`;启动首行 `unrecognized_model` 提示是本地模型清单校验,非网关错误,可忽略
- 用 `ANTHROPIC_AUTH_TOKEN` 而非 `ANTHROPIC_API_KEY`:网关只认 Bearer access key,AUTH_TOKEN 直接进 Authorization 头
- settings.json 属本机私有面,key 明文只落这里或 shell 私有段,永不入仓

## 2. Codex(config.toml 加 models.json,ZAI provider 指网关)

`~/.codex/config.toml`:

```toml
model = "glm-5.3"
model_provider = "zai"
model_reasoning_effort = "max"
model_catalog_json = "~/.codex/models.json"

[model_providers.zai]
name = "zai-overcast"
base_url = "http://192.168.88.10:8317/v1"
wire_api = "responses"
env_key = "OVERCAST_GATEWAY_KEY"
```

- `wire_api = "responses"`:codex 说 Responses wire,网关 xai-api-key 组原生直通智谱 `/api/v1/responses`,不经 chat 翻译(智谱 /api/v1 是 Responses-only 面,翻译必 403,见 config.example.yaml 纪律注)
- `base_url` 写到 `/v1`,codex 自接 `/responses`
- access key 走环境变量 `OVERCAST_GATEWAY_KEY`(先 export 再起 codex),不进 config.toml 明文;官方直连形用 `experimental_bearer_token` 写文件,与本网关形差异仅在 key 落点,直连形 base_url 是 `https://open.bigmodel.cn/api/v1`
- 2026-10-11 本机实测:codex exec 经网关 glm-5.3 得正确回答;首答 65 秒(glm thinking 模型首轮含会话建立),effort=max 后复测 11.8 秒

## 3. 通用 chat 客户端

OpenAI SDK 形:base-url `http://192.168.88.10:8317/v1`,端点 `/chat/completions`,模型名 `zp-glm53-codex`(chat 面 paas/v4 池);`glm-5.3` 与 `glm-5-turbo` 在 responses 池,chat 客户端也可用(网关代翻译)。

## 4. 验活(两发 200 即通)

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.88.10:8317/v1/messages \
  -H "Authorization: Bearer $OVERCAST_GATEWAY_KEY" -H 'anthropic-version: 2023-06-01' \
  -H 'Content-Type: application/json' \
  -d '{"model":"glm-5.3","max_tokens":32,"messages":[{"role":"user","content":"ping"}]}'

curl -s -o /dev/null -w '%{http_code}\n' http://192.168.88.10:8317/v1/responses \
  -H "Authorization: Bearer $OVERCAST_GATEWAY_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"glm-5.3","input":"ping","max_output_tokens":32}'
```
