## 1. Claude Code

settings env 形。

`~/.claude/settings.json` 的 env 段,接入相关键:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.88.10:8317",
    "ANTHROPIC_AUTH_TOKEN": "<任意非空串,如 overcast;开态才需真 key>",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "zp-cc-glm53fh[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "zp-cc-glm53[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "zp-cc-glm53[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": 1,
    "API_TIMEOUT_MS": "3000000"
  }
}
```

- DEFAULT 三件套(HAIKU/SONNET/OPUS)是接入关键:CC 内部按档位选模型,三档全指网关模型,旧 ANTHROPIC_MODEL/SMALL_FAST_MODEL 两键形会漏档位
- `[1m]` 后缀是 CC 客户端侧 1M 上下文参数。settings 写 `zp-cc-glm53[1m]` / `zp-cc-glm53fh[1m]`,CC 发请求前剥掉后缀,网关收到的是别名 `zp-cc-glm53` / `zp-cc-glm53fh`。网关别名本身不带 `[1m]`,带后缀直打会 400
- `CLAUDE_CODE_SUBAGENT_MODEL` 同步指 `zp-cc-glm53fh[1m]`;启动首行 `unrecognized_model` 提示是本地模型清单校验,非网关错误,可忽略
- 用 `ANTHROPIC_AUTH_TOKEN` 而非 `ANTHROPIC_API_KEY`:网关只认 Bearer access key,AUTH_TOKEN 直接进 Authorization 头
- settings.json 属本机私有面,key 明文只落这里或 shell 私有段,永不入仓

## 2. Codex

config.toml 加 models.json,ZAI provider 指网关。

`~/.codex/config.toml`:

```toml
model = "zp-cx-glm53"
model_provider = "zai"
model_reasoning_effort = "max"
model_catalog_json = "~/.codex/models.json"

[model_providers.zai]
name = "zai-overcast"
base_url = "http://192.168.88.10:8317/v1"
wire_api = "responses"
experimental_bearer_token = "<任意非空串,如 overcast;开态才需真 key>"
```

- `wire_api = "responses"`:codex 说 Responses wire,网关 xai-api-key 组原生直通智谱 `/api/v1/responses`,不经 chat 翻译(智谱 /api/v1 是 Responses-only 面,翻译必 403,见 config.example.yaml 纪律注)
- `base_url` 写到 `/v1`,codex 自接 `/responses`
- 鉴权两形,本机 2026-10-11 裁定用 `experimental_bearer_token`(官方形,key 落 config.toml,文件 600):交互起 codex 不依赖 shell 环境变量,herdr 窗格、新终端、非交互 shell 都免 export;`env_key = "OVERCAST_GATEWAY_KEY"` 形(先 export 再起 codex,key 不落文件)保留给不接受明文落盘的部署面,两者不可同写
- 客户端模型名用 `zp-cx-glm53`(上游 glm-5.3)与 `zp-cx-glm5t`(上游 glm-5-turbo),不要写裸上游名
- 2026-10-11 本机实测:codex exec 经网关 glm-5.3 得正确回答;首答 65 秒(glm thinking 模型首轮含会话建立),effort=max 后复测 11.8 秒

## 3. 通用 chat 客户端

OpenAI SDK 形:base-url `http://192.168.88.10:8317/v1`,端点 `/chat/completions`,模型名 `zp-cx-chat`(chat 面 paas/v4 池,上游 glm-5.3)。Codex 不要走这个名字,responses 用 `zp-cx-glm53` / `zp-cx-glm5t`。

## 4. 验活

两发 200 即通。

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.88.10:8317/v1/messages \
  -H "Authorization: Bearer $OVERCAST_GATEWAY_KEY" -H 'anthropic-version: 2023-06-01' \
  -H 'Content-Type: application/json' \
  -d '{"model":"zp-cc-glm53","max_tokens":32,"messages":[{"role":"user","content":"ping"}]}'

curl -s -o /dev/null -w '%{http_code}\n' http://192.168.88.10:8317/v1/responses \
  -H "Authorization: Bearer $OVERCAST_GATEWAY_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"zp-cx-glm53","input":"ping","max_output_tokens":32}'
```

## 5. 提速旋钮

2026-10-12 ov-04 研究与直探实证。

- **思考是延迟主体**:glm-5.3 与 glm-5.3-flash 强制思考,`thinking.type: disabled` 上游直接报错;唯一降档通道曾是 effort 的 zhipu 方言 `output_config.effort`,直探数字归档见 REQ-001 演进与 git 史 7bfb2c8
- **CC 侧 effort**:CC 原生 effort 旋钮翻译成 anthropic 标准参数,智谱不认;网关 payload 注入通道(`X-Overcast-Debug` 门控档)已于 2026-10-12 随能力二剔除(scope 收敛为双 token 轮换 + vector/CH 观测道),CC 面现无 effort 降档通道,提速靠权限模式与 [1m] 政策
- **权限模式**:CC auto 模式的安全分类器走主思考模型,网关忙即超时锁工具调用;ops 会话建议 acceptEdits 或手动确认(Shift+Tab 切换)
- **codex 侧**:`model_reasoning_effort` 日常 `high`(硬任务临时改回 `max`);`zp-cx-glm5t` 适合 20 万上下文内的短工具循环(该模型自行决定思考,非强制),档位 low/high/max 可选
- **[1m] 政策**:大上下文是长尾延迟主因(实测 232 发中 111 发 >=10s);日常会话不开 `[1m]` 并把压缩窗下调,长仓调查另开会话开 1M
- **网关侧无欠账**:代理开销与直打上游持平(对拍中位 2.69s vs 2.68s);keepalive/retry/session-affinity 全部保持现值(无稳态提速依据);anthropic 面无前缀缓存(同 key 同 1923-token 前缀两发 cache_read 均 0),affinity 无收益
